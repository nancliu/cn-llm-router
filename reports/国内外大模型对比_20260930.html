数据日期：2026-09-30（产品功能更新至 2026-10-05） 汇率口径：1 USD ≈ 7.2 CNY 对比模型：国产 6 头部 × 国外 5 旗舰 产品状态：cn-llm-router v0.3.0 · PyPI 已发布

1摘要结论：何时可放心用国产模型

结论先行。一句话：通用文本 / 编码 / 数据分析等主流场景，国产头部已与国外旗舰处于同一量级，且在成本与合规上有结构性优势；前沿极限能力尚缺同口径对标，需社区实测。

主流场景可放心用

国产头部 Qwen3.8-Max、DeepSeek-V4.1-Flash、GLM-5.3、Kimi-K3 在本项目加权能力分 68.1~70.8（SuperCLUE 通用榜头部区间 70.7~72.6）；LMArena Elo 已知值 1481~1500，与国外旗舰参考值 1505~1525 接近。

成本优势 6~117 倍

国产综合成本 1.6~52 元/百万tok，国外旗舰 25.9~187.2 元/百万tok。同口径下，DeepSeek-V4.1-Flash（4.4）对比 Claude Fable 5.1（187.2）约 42.5 倍，GLM-5.3-Flash（1.6）约 117 倍。

合规与直连便利

国产模型官方直连（阿里云百炼 / 智谱 / DeepSeek 官方 / Kimi 官方 / 火山方舟 / 腾讯云），无跨境数据传输，符合数据本地化要求；国外模型均需代理、无大陆官方接入点。

注意：前沿极限待验证

最新旗舰（Fable 5.1 / GPT-6 / Grok 4.7）未入 SuperCLUE 通用榜，其最新 Elo 也尚未收录，缺同口径 benchmark。最前沿推理 / 研究场景建议国产头部 + 社区实测验证。

5可用性与合规

成本之外，国产模型在接入便利与数据合规上有结构性优势。

国产模型：官方直连，无跨境合规风险

  • Qwen3.8-Max：阿里云百炼官方接入
  • GLM-5.3 / GLM-5.3-Flash：智谱 AI（bigmodel.cn）官方
  • DeepSeek-V4.1-Flash：DeepSeek 官方 API / 火山方舟
  • Kimi-K3：Kimi 开放平台官方
  • 豆包 Seed-2.1-Pro：火山方舟官方
  • 腾讯混元 Hy3：腾讯云 TokenHub 官方
  • 数据不出境，符合数据本地化与行业合规要求

国外模型：需代理，数据出境风险

  • Claude / GPT / Gemini / Grok 均无中国大陆官方 API 接入点
  • 需自备海外网络代理才能调用
  • Azure OpenAI 中国（21Vianet）不提供最新前沿模型
  • 请求与数据跨境传输，存在合规审查风险
  • 账单需海外支付方式，费率以美元结算

9产品能力全景：cn-llm-router

本报告所依托的选择器已演进为开源路由库（Python，PyPI 可安装）。打分表 v1 是它的评分底座；serve 网关 + litellm 桥接让 Claude Code / Codex 等 harness 直接以国产模型为后端运行。

评分体系 v1

12 类任务 × 3 级复杂度 × 15 模型，SuperCLUE 六维（数学推理/幻觉控制/科学推理/指令遵循/Agentic 编程/任务规划）+ Terminal 编程按类别权重加权；缺口标"待补充"，数字全部可溯源 URL。

三档性价比开关

纯能力优先 / 平衡（默认）/ 性价比优先，一档切换联动 36 格推荐（主选+备选+理由）。低复杂度偏性价比、高复杂度偏能力，成本权重可归零。

判类路由

model=auto 每请求 LLM 判类选型（180 golden cases 修复后 100% 通过）；model=点名 透传 + 同类别备选兜底；无 key 时走确定性规则兜底，分类仍可用。

透明转发铁律

不改写 prompt、不吞 tool 参数、流式原样、tool_call 原样往返——router 层不使能力变弱（ADR-0021）。工具参数丢失根因已修复并实测恢复。

路由可见性

每次请求 INFO 日志 + GET /v1/routes 最近 50 条：时间/类别/复杂度/选中模型/策略/耗时/tokens，成功失败都记录，失败含 attempted 与错误摘要。

可靠性与发布

serve 单实例守护（端口占用自动关旧启新）、每 10 分钟自愈计划任务 + 登录自启、provider enabled 开关（套餐停用即摘出路由）、PyPI v0.3.0（0.1/0.2/0.3 均在线上）。

12接入配置：Claude Code 与 Codex

两份最小配置即可让主流 harness 跑在国产模型上。注意：若使用 cc-switch 管理 provider，请在其 UI 中添加自定义 provider 后切换——直接改配置文件会被 cc-switch 覆盖。

Claude Code（经 litellm 4000）

# 启动网关 powershell -File scripts/start-gateway.ps1 # 环境变量（cc-switch 中配置，勿手改 settings.json） ANTHROPIC_BASE_URL=http://127.0.0.1:4000 ANTHROPIC_AUTH_TOKEN=sk-router-bridge ANTHROPIC_MODEL=router-auto ANTHROPIC_SMALL_FAST_MODEL=router-auto

router-auto = 每请求判类路由；router-qwen / router-ced = 点名透传。

Codex（直连 serve 10041）

[model_providers.cn-llm-router] name = "cn-llm-router" base_url = "http://127.0.0.1:10041/v1" wire_api = "chat" # 使用：codex --provider cn-llm-router --model auto

wire_api 支持 "chat" 与 "responses" 双值；本项目实测 chat 兼容最优。

litellm 两个已知启动坑均已固化为脚本：① 启动前清机器级 DATABASE_URL（12-factor 同名变量，会误连 PostgreSQL 崩溃）；② 配置文件保持纯 ASCII（中文 Windows 上 litellm 用 GBK 默认编码读 YAML，UTF-8 中文注释会启动即崩）。
