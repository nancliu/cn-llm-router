# ADR-0001：评分口径与选择策略

- 状态：Accepted
- 日期：2026-09-23
- 决策人：nancliu（经多轮方案讨论确认）

## 背景

做一个国内大模型选择器：把请求识别为任务类别 + 复杂度，再推荐并路由到最合适的国产大模型。需要一套公开、可复现、可被社区审查的评分与选择口径，作为开源项目的地基。

## 决策

1. **任务分类**：12 个大类（程序编码、前端UX设计、文书撰写、数据分析、数学推理、Agent编排、长文档处理、翻译润色、多模态理解、知识问答/检索、创意生成、代码审查与调试）；每类 3 级复杂度（低/中/高）。
2. **能力分**：以 SuperCLUE 六维度（数学推理/幻觉控制/科学推理/精确指令遵循/Agentic编程/Agent任务规划）按任务加权推导；无 Terminal 分的模型用 Agentic×1.05（上限 95）代理；叠加社区/人工评测信号（有量化来源才计入），并按评测日期做时效衰减。拿不到真实数字的格子标"待补充"，不编造。
3. **成本**：综合成本 = 输入单价×0.6 + 输出单价×0.4（元/百万 tokens，取官方平台价）。
4. **选择策略三档**（默认"平衡"）：
   - 纯能力优先：成本权重=0，仅按能力分排序，同分取成本低者；
   - 平衡：低复杂度偏性价比、中复杂度平衡、高复杂度偏能力；
   - 性价比优先：按性价比指数 = 平均能力分 / 成本指数 排序，能力分 < 50 设门槛。
5. **数据落地**：模型注册表 + 能力评分矩阵 + 推荐策略落在打分表（v1-20260923，飞书表格）；口径说明 Sheet 含评分公式、权重矩阵、来源 URL 清单（40 条）与待补充项清单。

## 权衡

- 纯公开榜单有滞后与刷榜风险 → 用多源 + 评测日期衰减缓解，缺口显式标注。
- 任务权重存在主观性 → 权重矩阵单独成表可调；调整影响推荐时需更新本 ADR 或新增 ADR。
- 闭源模型信息不透明（价格/上下文口径冲突）→ 以官方平台为准并记录冲突项待核实。

## 影响

- 后续路由层代码直接消费评分矩阵（导出 CSV/JSON）。
- 模型版本更新/价格变动 → 刷新注册表与评分矩阵（建议做定时刷新管线）。
- 打分表 v1 初版覆盖 15 个模型；Hy4-preview、讯飞星火 X2.5 等无 SuperCLUE 成绩的模型能力分待补充。
