# ADR-0006：复杂度口径校准（golden cases 标注 + 分类器 prompt 锚点）

- 状态：accepted
- 日期：2026-09-23
- 关联：ADR-0001、ADR-0002

## 背景

在线评测（2026-09-23，108 golden cases）显示三模型**复杂度命中率系统性偏低**（68-74%），但类别命中率高达 97-99%。逐题分析发现：

- 108 题中 28 题（26%）落在相邻档边界（低↔中 14、中↔高 13），真正的跨档错判仅 1 题（0.9%）；若按"±1 档算命中"，三模型均达 97-99%。
- LLM 呈**向中档收缩**倾向：边界题被拉向"中"。
- 人工抽查题面：标注与 LLM 判断**各有道理**（`∫x·e^x dx` 标"中"偏高、"50 页报告总结"标"低"偏低），属档位切分点不同，非分类能力问题。
- 根因：分类器 prompt 的复杂度定义过模糊（"低=简单直接，中=常规任务，高=多步骤/专业深度"），LLM 无法稳定对齐标注尺度。

## 决策

双向校准（组合拳）：

1. **校准 golden cases 标注**（评估基准侧）：依据三模型多数判向 + 人工按新锚点定义终裁，修正 15 题复杂度标注（低→中 6、中→低 6、中→高 3，详见 `scripts/calibrate_complexity.py` 的 CALIBRATIONS 表）。原值保留在 yaml 行尾注释 `# 校准2026-09-23: 原=X`，可回滚可追溯。校准后分布 38/33/37（低/中/高）。
2. **分类器 prompt 加复杂度判断锚点**（分类器侧）：明确三档特征（低=单一步骤/模板化；中=多步骤但路径清晰/需设计或归纳；高=系统性设计/多轮迭代/边界条件/正确性/归因），并指示"按步骤数+设计深度+迭代轮次中最强信号定档，不要默认取中"。
3. **指标透明化**：评测报告同时报告精确命中率与 ±1 档命中率；复杂度作为模糊尺度，±1 档为准入门槛。

## 为什么

- 只调一侧会留偏差：只改标注 → prompt 依旧模糊（LLM 继续向中收缩）；只改 prompt → 基准仍偏离真实判断（命中率虚低）。
- 边界题标注本就是主观切分，多数模型判向 + 人工终裁给出可复现、可审计的校准依据。

## 备选

- **只改指标（±1 档为主指标）**：不动基准——标注失真依旧存在，prompt 模糊依旧，仅掩盖问题，否。
- **只调 prompt**：基准不动，命中率仍受旧标注拖累，无法验证 prompt 是否收敛，否。

## 影响

- `tests/fixtures/golden_cases.yaml`：15 题复杂度值变更（带原值注释）。
- `cn_llm_router/classifier.py`：prompt 增加复杂度锚点段。
- 评测报告新增校准后版本 `reports/eval-cn-plan-calibrated-20260923.json`，用于验证收敛。
- 规则兜底不受影响（复杂度不参与规则判类，恒为"中"）。
