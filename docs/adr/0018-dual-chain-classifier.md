# ADR-0018：双模型分类分流（方案 A）

- 状态：accepted
- 日期：2026-09-29
- 关联：ADR-0002（分类器）、ADR-0017（面板多线程）

## 背景

ADR-0002 默认分类链 Qwen3.8-Max-0902 → CED → 豆包，端到端 99.44%（180 题）最优，
但 Qwen 分类单次约 10~20s（1922s/180 题），面板与 CLI 感知"慢"。max_tokens 精简
（ADR-0017 后一次尝试）验证无效：瓶颈在 TTFT 与输入侧处理，不在输出长度。

而 CED（DeepSeek-V4.1-Flash-CED）端到端 98.89%、速度快约 6 倍（316s），
但 VLM 真实图文实测仅 65%（Qwen 100%）——纯文本分类足够，真实图片理解不可靠。

## 决策

**分类前按 prompt 视觉信号分流，两条候选链：**

- prompt 命中视觉信号词（图片/截图/设计稿/多模态等 31 词，可配置）→ 主链
  `classifier_models`（Qwen3.8-Max-0902 → CED → 豆包）
- 未命中 → 快速链 `classifier_text_chain`（DeepSeek-V4.1-Flash-CED → Qwen → 豆包）

理由：
- 分类层 CED 与 Qwen 只差 0.55pp（1/180），但对**真实图片任务**的推荐链正确性
  Qwen 显著更好（VLM 100% vs 65%）——视觉信号命中即走 Qwen，保证下游推荐 VLM 强模型；
- 纯文本任务（绝大多数）走 CED 快速链，端到端准确率 98.89% 保持；
- 缓存键改为"实际使用的模型链"，两条链缓存隔离，不串结果。

## 实测（180 golden cases，2026-09-29）

| 路径 | 题数 | 命中 | 说明 |
|---|---|---|---|
| Qwen（视觉信号命中） | 16 | 16/16 | 含 14/15 多模态理解类 |
| CED（纯文本） | 164 | 162/164 | 错 agent-high-3（Agent编排→程序编码）、ld-low-5 |
| **混合合计** | 180 | **178/180 = 98.89%** | 耗时估算 719s，较全 Qwen 1845s **提速 2.6x** |

对照：全 Qwen 99.44% / 1845s；全 CED 98.89% / 610s（但 VLM 推荐链不可靠）。
混合方案 = 以 1 题（0.55pp）分类准确率换 2.6x 速度 + 保住多模态推荐链。

## 配置

`config/classifier.yaml`：
- `text_chain`：纯文本快速链（默认 CED → Qwen → 豆包）
- `multimodal_keywords`：视觉信号词表（默认 31 词，内置兜底；命中走 `models` 主链）
- `models`：主链不变（默认 Qwen → CED → 豆包）

## 影响

- `classifier.classify` 行为：模型链动态选择，`last_model` 记录实际模型（统计可用）；
- 缓存键含实际链，两条链不共享缓存条目；
- 评测脚本（`eval_classifier.py --models X`）固定单链评测仍有效（单模型能力基线）；
- 混合准确率的精确值随实际 prompt 分布变化（模拟基准 98.89% 基于 180 题固定分布）。
