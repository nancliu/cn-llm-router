# ADR-0002：任务分类器采用 LLM 结构化判类

- 状态：accepted
- 日期：2026-09-23
- 关联：ADR-0001（评分口径与选择策略）

## 决策

任务分类器用**可配置的 LLM 结构化判类**：把请求交给模型，强制输出 JSON `{category, complexity, confidence, second_guess}`。不训练小型分类器，也不把 embedding/规则作为主路径。

## 为什么

- 无标注数据：训练分类器需要标注集，项目起步阶段没有；
- 边界质量：12 类 × 3 级复杂度的边界场景多，规则/嵌入的精度弱；
- 成本低：分类请求极小（几百 token），用性价比档模型即可。
- 分类模型独立可配，默认性价比档（GLM-5.3-Flash），后续可用"分类准确率评测"替换。

## 细化（2026-09-23 第 2 轮确认）

- 输出 JSON：`{category, complexity, confidence, second_guess}`；`raw_reason` 仅 debug 模式输出。
- 降级链：LLM 失败 → 规则关键词快速兜底（命中明确关键词直接定类）→ 默认值"知识问答/检索 + 中复杂度"兜底；两层均标记 `low_confidence` 并带降级原因，不静默。

## 备选

- **Embedding + 关键词/规则混合**：离线免费，但中文本地嵌入模型选择成本高、边界质量弱 → 仅作为 LLM 不可用时的兜底路径。
- **训练小型分类器**：需要标注数据与训练管线，当前过重。
