# ADR-0005：按供应商可用性过滤推荐（可配置关闭）

- 状态：accepted
- 日期：2026-09-23
- 关联：ADR-0001、ADR-0003、ADR-0004

## 决策

选择器**默认只在"可用集"内推荐**：可用性 = 该模型所属 provider 的 API key 环境变量已配置（加载时一次性探测）。未配 key 的模型不参与主选/备选排序；若全配齐时的首选被过滤，结果元数据 `notice` 附提示"配置 X key 后可换 Y"。

同时提供配置开关 `selector.availability_filter`（默认 `true`）：设为 `false` 时从**全量集**比较选择，用于"先看结论再补 key"的计划场景（此时调用可能因缺 key 失败，由网关返回结构化错误）。

## 为什么

- 保证"推荐即能用"：默认行为不产出不可调用的推荐；
- 保留可操作性：全集对比模式让用户看到"补齐 key 的上限是什么"，且提示不打断流程；
- 可用性判定简单可靠：只看 key 是否配置，不做在线探测（避免启动期网络依赖）。

## 备选

- **不过滤**：推荐照常、调用时才报错——用户拿到的是不能用的推荐，否。
- **在线健康探测**：启动时探活各端点——增加网络依赖与延迟，v1 不做。

## 影响

- 分类器同理：默认分类模型按"候选模型列表"取第一个可用者，全不可用才走规则兜底（见 ADR-0002）。
